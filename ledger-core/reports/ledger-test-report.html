2. Tamper detection (T5)

A database superuser switched off every trigger and attacked the ledger four ways. Each attack was rolled back after the check. Verify ledger recomputes every SHA-256 link independently in Python and compares the chain with the digest already emailed out of the system. The fourth attack rewrote the whole chain and the stored anchors, so the database was internally consistent: only the emailed digest could expose it, and it did.

6. Limits, stated plainly

  • This proves the ledger rules in the database. It does not test the user interface, hosting security (that is the VAPT by a CERT-In-empanelled auditor) or e-mail delivery of the digest.
  • A change made on the same day before the evening digest is sent is not caught by the digest; it is bounded by the collector's signed paper voucher and the privileged-session log.
  • Tampering becomes evident, not impossible. No blockchain is used or needed.
